# Концепция уровней игры «Путь пакета»
## Документ для диплома — образовательная игра по сетевым технологиям

---

## Что это за игра

Unity WebGL-игра для браузера (ПК). Жанр — образовательная головоломка.

Игрок управляет персонажем на клеточном поле 8×8, вводя последовательность команд. Задача — дойти до целей в правильном порядке, используя ограниченный набор команд.

**Интерфейс:** физические 3D-кнопки на игровом устройстве. Команды: Up, Down, Left, Right, While.

---

## Нарратив (лор)

**Игрок = пакет данных.**

Пользователь в офисе открыл браузер и перешёл на сайт. Игрок — это ответ сервера, который должен добраться до компьютера пользователя через всю сетевую инфраструктуру.

Путь пакета: **дата-центр → сеть провайдера → последняя миля → офис → рабочий стол.**

Каждый уровень — один участок этого пути. Каждая цель на уровне — реальное сетевое устройство, через которое проходит трафик.

---

## Метафоры игровых механик

Все механики имеют точное соответствие в реальных сетевых технологиях:

| Игровая механика | Сетевая концепция | Пояснение |
|---|---|---|
| Движение по клеткам | Передача пакета между узлами | Пакет переходит от устройства к устройству (hop-by-hop) |
| Строгий порядок целей | Routing sequence / forwarding path | Нельзя миновать промежуточный узел — данные идут по цепочке |
| Стены | Firewall / ACL-правила / занятые маршруты | Часть путей закрыта политиками безопасности или перегрузкой |
| Ямы | Packet loss / Collision domain | Зона помех или коллизий — пакет уничтожается |
| While (движение до упора) | Forwarding вдоль сегмента / кабельной трассы | Пакет распространяется по L2-сегменту до следующего барьера |
| Лимит команд | TTL (Time to Live) | У каждого пакета ограниченное число прыжков — защита от петель |
| Reset (сброс к чекпоинту) | TCP Retransmission | При потере пакета TCP повторяет отправку с последней подтверждённой точки |
| Full Restart | Разрыв соединения и новая сессия | Полный сброс — как закрыть и заново открыть соединение |

### Уровень 0 — Туториал «Первый пакет»

**Подзаголовок:** "Учимся двигаться"

**Лор:**
> Ты только что родился на сервере. Тебе нужно дойти до первого узла — сетевого порта. Никаких преград, никаких правил. Просто иди.

**Механика:**
- 1 цель
- Нет стен, нет ям, нет While
- TTL отключён

**Цель:** Network Port (выход с сервера в сеть)

**Образовательный акцент:**
- Что такое пакет данных
- Интернет передаёт данные маленькими кусочками — пакетами
- Как работают команды управления

**Реальность:** Концепция пакетной передачи данных — основа стека TCP/IP (RFC 791). Все данные в интернете разбиваются на пакеты, каждый путешествует независимо.

---

### Уровень 1 — «Дата-центр»

**Подзаголовок:** "Как рождаются данные"

**Лор:**
> Внутри дата-центра всё строго. Сначала данные нужно забрать из базы, потом сервер соберёт из них ответ, и только потом коммутатор отправит тебя в интернет. Пропустить шаг нельзя.

**Механика:**
- 3 цели в строгом порядке
- Нет стен, нет ям, нет While
- TTL: мягкий

**Маршрут (строго по порядку):**
1. **База данных (Database Server)** — хранит данные (таблицы, записи, файлы)
2. **Сервер приложений (Application Server)** — обрабатывает запрос, формирует ответ
3. **Серверный коммутатор (Top-of-Rack Switch)** — соединяет серверы внутри стойки, отправляет трафик дальше

**Ключевая идея уровня:**
Данные не «летят» напрямую. Внутри дата-центра тоже есть инфраструктура — коммутаторы, маршрутизаторы. Коммутатор — ключевое устройство передачи даже на серверном уровне.

**Образовательный акцент:**
- Трёхзвенная архитектура: хранение данных → обработка данных → передача данных
- Разница между типами серверов
- Почему порядок обработки имеет значение

**Реальность:** Трёхзвенная архитектура (3-tier architecture) — стандарт индустрии для веб-приложений. Top-of-Rack Switch — реальный тип коммутатора, устанавливается в верхней части серверной стойки и агрегирует трафик всех серверов в ней.

---

### Уровень 2 — «Сеть провайдера»

**Подзаголовок:** "Маршруты и файрволы"

**Лор:**
> Ты вышел из дата-центра и попал в сеть интернет-провайдера. Здесь не все пути открыты: файрволы блокируют опасные направления, а некоторые маршруты перегружены. Нужно найти разрешённый путь.

**Механика:**
- 3 цели
- **Появляются стены** — файрволы / ACL-правила / занятые маршруты
- Нет ям, нет While
- TTL: средний

**Маршрут:**
1. **Агрегационный коммутатор (Aggregation Switch)** — собирает трафик от множества серверов или подсетей дата-центра
2. **Пограничный маршрутизатор (Edge Router)** — граница между дата-центром и интернетом, первый L3-узел
3. **Магистральный маршрутизатор (Backbone Router)** — передаёт данные между городами и странами по магистральным каналам

**Ключевая идея уровня:**
Коммутатор (Switch) работает **внутри** одной сети — передаёт кадры по MAC-адресам (уровень L2).
Маршрутизатор (Router) работает **между** разными сетями — маршрутизирует пакеты по IP-адресам (уровень L3).
Это фундаментальное различие модели OSI.

**Образовательный акцент:**
- Модель OSI: L2 (канальный) vs L3 (сетевой) уровень
- Что такое маршрутизация (routing)
- Интернет — это «сеть сетей», а не единый канал
- Для чего нужны файрволы (ACL, политики доступа)

**Реальность:** Иерархия Aggregation Switch → Edge Router → Backbone Router — стандартная архитектура сети провайдера (ISP network hierarchy). Backbone роутеры работают на протоколе BGP (Border Gateway Protocol) — основном протоколе маршрутизации интернета.

### Уровень 3 — «Последняя миля»

**Подзаголовок:** "Самый ненадёжный участок"

**Лор:**
> Ты почти добрался. Осталась последняя миля — от узла провайдера до здания офиса. Это самый проблемный участок: здесь теряются пакеты, рвутся соединения, пропадает сигнал. Именно поэтому «у соседа есть интернет, а у меня нет».

**Механика:**
- 3 цели
- Стены (физические барьеры, занятые кабельные трассы)
- **Появляются ямы** — зоны потери пакетов, коллизионные домены
- Нет While
- TTL: жёсткий

**Маршрут:**
1. **Узел доступа провайдера (OLT — Optical Line Terminal)** — точка подключения абонентов в оптических сетях GPON
2. **Домовой коммутатор (Building Switch)** — распределяет интернет по подъездам / этажам здания
3. **Офисный маршрутизатор (Office Router)** — вход в локальную сеть офиса, NAT, DHCP

**Ключевая идея уровня:**
«Последняя миля» — термин из телекоммуникаций, обозначающий финальный участок сети от провайдера до абонента. Статистически именно здесь происходит большинство сбоев: обрывы физического кабеля, помехи, перегрузка узлов доступа.

**Образовательный акцент:**
- Что такое «последняя миля» (last mile) в телекоммуникациях
- Packet loss — нормальное явление в реальных сетях
- Именно поэтому TCP имеет механизм повторной передачи (retransmission) — аналог Reset в игре
- Почему зона ответственности провайдера заканчивается на границе с оборудованием абонента

**Реальность:** OLT (Optical Line Terminal) — реальное устройство, использующееся в сетях GPON (Gigabit Passive Optical Network). Это стандарт подключения большинства современных домов к интернету через оптоволокно. Концепция «последней мили» — устоявшийся термин в телекоммуникациях.

### Уровень 4 — «Локальная сеть офиса»

**Подзаголовок:** "Последний прыжок"

**Лор:**
> Ты уже в офисе. Осталось совсем немного — найти нужный компьютер. Локальная сеть офиса устроена сложно: длинные кабельные трассы, изолированные сегменты, перегороженные коридоры. Но теперь у тебя есть While — команда, которая гонит пакет по кабелю до самого конца.

**Механика:**
- 3 цели
- Стены (VLAN-сегменты, физические перегородки)
- Ямы (broadcast storm, коллизионные домены в старом Ethernet)
- **Появляется While** — forwarding вдоль кабельной трассы
- TTL: очень жёсткий (без While не уложиться)

**Маршрут:**
1. **Ядровой коммутатор (Core Switch)** — главный узел офисной сети, агрегирует всё здание
2. **Коммутатор доступа (Access Switch)** — коммутатор этажа или отдела, подключает конечные устройства
3. **Рабочая станция (Workstation)** — компьютер сотрудника, конечная точка пути

**Ключевая идея уровня:**
While = forwarding в L2-сегменте. Пакет движется по кабелю, не принимая решений, до тех пор пока не упрётся в следующее устройство. Без этой команды уровень невозможно пройти в рамках TTL — нужно мыслить эффективно.

**Образовательный акцент:**
- LAN (Local Area Network) vs WAN (Wide Area Network) — игрок прошёл весь путь от WAN до LAN
- Двухуровневая архитектура LAN: Core → Access → End device
- Топология офисной сети
- VLAN как метод изоляции сегментов сети

**Реальность:** Core Switch → Access Switch → Workstation — стандартная двухуровневая LAN-архитектура (collapsed core design), описанная в документации Cisco и стандартах IEEE 802.

### Уровень 5 — «DNS: Найди адрес»

**Подзаголовок:** "Прежде чем отправить — узнай куда"

**Лор:**
> Прежде чем первый пакет ушёл с сервера, произошло кое-что важное. Браузер пользователя не знал IP-адреса сервера. Он спросил у DNS. DNS — это телефонная книга интернета. Теперь ты — DNS-запрос, который ищет ответ.

**Механика:**
- 4 цели (DNS-цепочка длиннее стандартной)
- Все механики активны (стены + ямы + While)
- TTL: жёсткий
- Этот уровень концептуально «выпадает» из основного нарратива — это флэшбэк, показывающий что происходило до начала путешествия пакета

**Маршрут:**
1. **Рекурсивный резолвер (Recursive Resolver)** — DNS-сервер провайдера, первая точка обращения
2. **Корневой сервер (Root Name Server)** — знает адреса всех TLD-серверов (.com, .ru и т.д.)
3. **TLD-сервер (.com / .ru)** — знает адреса авторитативных серверов для конкретных доменов
4. **Авторитативный сервер (Authoritative NS)** — хранит реальный IP-адрес домена

**Ключевая идея уровня:**
DNS-резолвинг — итеративный процесс. Браузер не знает ничего напрямую — он спрашивает у резолвера, тот идёт по цепочке: корень → TLD → авторитативный. Только получив IP-адрес, пакет вообще может отправиться в путь.

**Стены:** кешированные записи (часть пути пропускается, часть закрыта — NXDOMAIN, SERVFAIL)
**Ямы:** несуществующие домены — запрос попадает в «яму» и теряется

**Образовательный акцент:**
- Что такое DNS (Domain Name System)
- Почему URL (google.com) нужно преобразовывать в IP-адрес
- Иерархия DNS: корневые серверы → TLD → авторитативные
- Что происходит когда DNS недоступен — и почему «сайт не открывается, хотя интернет есть»

**Реальность:** Схема DNS-резолвинга описана в RFC 1034/1035 (1987). Корневых серверов в мире 13 логических единиц (A–M), физически их более 1500 по всему миру. Именно эту цепочку проходит каждый запрос при первом обращении к домену.

### Уровень 6 — «Резервный маршрут»

**Подзаголовок:** "Сети не умирают"

**Лор:**
> Основной маршрут упал. Кабель перерезан, маршрутизатор перегружен. Но сеть не останавливается — она автоматически переключается на резервный путь. Ты должен найти его.

**Механика:**
- 3 цели
- Все механики активны (стены + ямы + While)
- TTL: жёсткий
- Уровень-загадка: очевидный путь заблокирован стеной, нужно найти обходной маршрут

**Маршрут:**
1. **Основной маршрутизатор (Primary Router)** — упал (закрыт стеной — недоступен напрямую)
2. **Резервный маршрутизатор (Backup Router)** — принял трафик на себя по протоколу OSPF/HSRP
3. **Точка восстановления (Recovery Node)** — трафик вернулся в основной канал

**Ключевая идея уровня:**
Надёжные сети строятся с резервированием (redundancy). Протоколы STP, OSPF, HSRP, VRRP автоматически перестраивают маршруты при отказе узла. Это объясняет почему интернет «не падает» при выходе из строя отдельных кабелей или роутеров.

**Образовательный акцент:**
- Зачем нужно резервирование в сетях
- Протоколы отказоустойчивости: OSPF (динамическая маршрутизация), STP (Spanning Tree — защита от петель)
- HSRP/VRRP — виртуальный IP на двух роутерах, один из которых резервный
- Принцип «интернет спроектирован так, чтобы пережить ядерный удар» (изначальная цель ARPANET)

**Реальность:** Протокол OSPF (Open Shortest Path First, RFC 2328) — один из основных протоколов динамической маршрутизации, позволяет автоматически перестраивать маршруты при отказе узла. HSRP (Hot Standby Router Protocol) — протокол Cisco для резервирования шлюза. Концепция отказоустойчивости — базовое требование к сетевой инфраструктуре.

### Уровень 7 — «Wi-Fi: Последний прыжок»

**Подзаголовок:** "Без провода"

**Лор:**
> Ты добрался до роутера. Последний прыжок — беспроводной. Wi-Fi работает иначе, чем провод: все устройства делят одну среду передачи, сигнал ослабевает через стены, соседние сети создают помехи. Добраться до ноутбука сложнее, чем кажется.

**Механика:**
- 3 цели
- Все механики активны (стены + ямы + While)
- **Ям значительно больше**, чем в предыдущих уровнях — зоны помех и коллизий в беспроводной среде
- TTL: жёсткий

**Маршрут:**
1. **Домашний/офисный роутер (Wi-Fi Router)** — раздаёт беспроводной сигнал
2. **Точка доступа (Access Point)** — расширяет покрытие Wi-Fi в отдалённых зонах
3. **Устройство пользователя (Laptop / Smartphone)** — финальная точка доставки

**Ключевая идея уровня:**
Wi-Fi — shared medium. В отличие от проводного Ethernet, все устройства в зоне покрытия «слышат» друг друга. Это порождает коллизии (CSMA/CA — механизм избегания коллизий), ухудшение сигнала от помех, нестабильную пропускную способность. Именно поэтому Wi-Fi медленнее и менее надёжен, чем провод.

**Стены:** физические препятствия для радиоволн (стены, перекрытия, металлические конструкции)
**Ямы:** зоны интерференции — другие Wi-Fi сети на том же канале, микроволновые печи (2.4 ГГц), Bluetooth

**Образовательный акцент:**
- Принципиальное отличие проводной и беспроводной передачи
- Стандарты Wi-Fi: IEEE 802.11a/b/g/n/ac/ax (Wi-Fi 6)
- Частоты 2.4 ГГц vs 5 ГГц: дальность против скорости
- CSMA/CA (Carrier Sense Multiple Access with Collision Avoidance) — почему Wi-Fi замедляется при большом числе устройств
- Почему провод надёжнее для критически важных задач

**Реальность:** Wi-Fi работает по стандарту IEEE 802.11. CSMA/CA — реальный механизм, описанный в стандарте: перед передачей устройство «слушает» эфир и ждёт, пока канал освободится, чтобы избежать коллизий. 2.4 ГГц действительно пересекается с диапазоном микроволновых печей (2.45 ГГц).

## Общая образовательная дуга

```
Уровень 0: Что такое пакет данных?
      ↓
Уровень 1: Как данные рождаются — серверная инфраструктура
      ↓
Уровень 2: Как данные путешествуют — маршрутизация в интернете
      ↓
Уровень 3: Где возникают проблемы — последняя миля, packet loss
      ↓
Уровень 4: Как данные доходят до тебя — локальная сеть
      ↓
Уровень 5: Как пакет вообще знает куда идти — DNS
      ↓
Уровень 6: Почему сеть не умирает — резервирование
      ↓
Уровень 7: Почему Wi-Fi хуже провода — беспроводная среда
```

Игрок, прошедший все уровни, понимает полный жизненный цикл сетевого запроса: от DNS-резолвинга до физической доставки пакета на устройство — и знает где и почему могут возникать проблемы.

## Соответствие реальным концепциям

Все уровни основаны на реальных сетевых технологиях:

| Уровень | Стандарты и протоколы |
|---|---|
| 0 | TCP/IP, RFC 791 (IP), пакетная коммутация |
| 1 | 3-tier architecture, Top-of-Rack switching |
| 2 | OSI L2/L3, BGP (RFC 4271), ACL, Firewall |
